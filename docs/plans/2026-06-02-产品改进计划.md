# 产品改进计划

> **Status:** 提议中

**Goal:** 解决产品审查中发现的核心问题——AI 链路首次成功率、边缘离线容灾、节点库认知负担、手动建模降级路径。

**Architecture:** 以前端改动为主，涉及 copilot 面板、节点库、设备建模 UI、离线检测与降级提示。可能新增 1 篇 ADR（AI 离线策略）。

**Tech Stack:** TypeScript / React 19 / Rust（离线检测）/ Vitest

---

## 背景

2026-06-02 产品审查结论：

1. 引擎工程完成度极高（30 篇 ADR、87 条 IPC、29 种节点、三段式 DSL 全链路），但产品对目标用户的使用场景、信任建立路径和断网容灾考虑不足。
2. 产品已全面押注 AI 作为建模唯一入口（RFC-0006），这意味着 AI 链路的首次成功率直接决定用户留存。
3. "边缘原生"与"AI 增强"需要共存策略——copilot 断网时不能静默失败。

完整审查记录见本文件末尾附录。

## 附录：产品审查完整结论

### 做得好的部分

- **工程纪律教科书级**：30 篇 ADR、5 篇 RFC、AGENTS.md 真值源约定、文档触发矩阵。在工业软件领域本身就是竞争力（客户审计时可以展示完整的决策追溯）
- **三段式 DSL 设计直觉正确**：Device → Capability → Workflow 映射 ISA-95 经典模式。安全编译器 6 条规则是工业刚需
- **连接治理工业级**：ConnectionManager + RAII Guard + 熔断器 + 健康监控 + 并发限流，同类产品通常到 v2.0 才认真做
- **Backpressure 设计**：100ms 定时窗口 + 队列深度监测 + 边热力图可视化
- **技术选型保守且正确**：Rust + Tauri + React，SQLite 本地存储，零 HTTP/gRPC 依赖

### 核心问题

1. **产品定位在"工具平台"和"行业解决方案"之间悬而未决**——但结论是押注 AI 让用户自建 anything，不需要预置模板
2. **Copilot 产品角色仍在摇摆**——RFC-0006 做了大胆的"唯一入口"决策，但缺少离线降级和手动 fallback
3. **"边缘原生"承诺与 AI 在线依赖存在矛盾**——需要 ADR 明确离线行为
4. **29 种节点认知负担高**——需要分层展示，低层协议节点不应与业务语义节点平级
5. **AI 链路首次成功率是核心赌注**——需要黄金路径验收守住底线
